How the quality chain & strict mode actually behave

The chain is read left-to-right. The first sample rate the catalogued asset is published in wins; the rest of the list is fallback, never an upgrade path. So a chain of 48000, 44100, 96000, 192000 means:

  1. Try 48 kHz. If the album has it, download at 48 kHz and stop.
  2. Otherwise try 44.1 kHz. If present, take that.
  3. Only after those fail will it consider 96 kHz, then 192 kHz.

That's what you want 95% of the time: pin a sane ceiling and let oddball Hi-Res releases come in higher only if you have nothing lower. Put 192000 first only if disk space is free and you want the "always grab the biggest" behaviour.

Strict Mode

With Strict Mode on, the queue refuses to fall back past the first chain entry without an explicit confirm. Useful for "I want 48 kHz or nothing, never let me silently get 44.1" workflows. Off by default; most users prefer the silent fall-through.

Skip If Exists

Heuristic: if the destination folder already contains one or more audio files, the job is marked skipped instead of re-downloaded. Cheap idempotency for cron / repeated paste-the-same-URL flows. Skip-MV-split album jobs always force this off — they need to add new audio tracks alongside whatever's already there.
